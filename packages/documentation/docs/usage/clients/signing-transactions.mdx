## Overview

Providers, if supported, can sign single, atomic or multiple transactions. If the provider also supports it, the provider can sign transactions using multisigs and re-keyed accounts.

## Signing a single transaction

Regardless of whether a client is sending multiple/atomic transactions or a single transaction, an array of base64 encoded transactions will need to be provided.

<Tabs
  defaultValue="javascript"
  values={[
    { label: 'Javascript', value: 'javascript' },
    { label: 'TypeScript', value: 'typescript' },
  ]}>
  <TabItem value="javascript">

  ```js
  const algosdk = require('algosdk');

  // create a transaction
  try {
    const algodClient = new algosdk.Algodv2(
      'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa',
      'http://localhost',
      '4001',
    );
    const encoder = new TextEncoder();
    const suggestedParams = await algodClient.getTransactionParams().do();
    const transaction = algosdk.makePaymentTxnWithSuggestedParamsFromObject({
      amount: algosdk.algosToMicroalgos(1),
      from: 'P3AIQVDJ2CTH54KSJE63YWB7IZGS4W4JGC53I6GK72BGZ5BXO2B2PS4M4U',
      note: encoder.encode('Hello Human!'),
      suggestedParams,
      to: '6GT6EXFDAHZDZYUOPT725ZRWYBZDCEGYT7SYYXGJKRFUAG5B7JMI7DQRNQ',
    });
    const transactionBytes = transaction.toByte();
  } catch (error) {
    // handle error
  }

  client.onSignTransactions(({ error, result }) => {
    if (error) {
      console.error('error:', error);

      return;
    }

    console.log(result);
    /*
    {
      stxns: [
        'gqNzaWfEQ...',
      ],
    }
    */
  });

  // send a sign transactions request
  client.signTransactions({
    params: {
      txns: [
        {
          txn: btoa(String.fromCodePoint(...transactionBytes)), // convert to base64 string
        },
      ],
    },
    vcic: 'q5dQ...',
  });
  ```

## Signing atomic transactions

When sending atomic transactions, regardless of whether the provider is signing only some of the transactions, all transactions must be sent.

## Non-provider signed transactions

In the case when a provider being sent multiple transactions, but the provider only needs to sign a subset of the transactions, an empty `signers` array **MUST** be used. This instructs the provider to skip the transaction, even if it can sign it.

For example:

## Signing transactions with multisig accounts

When using multisig accounts to sign transactions, a few extra options **MUST** be provided to the params object.

The transaction must now include the `msig` object that conforms to [`algosdk.MultisigMetadata`](https://algorand.github.io/js-algorand-sdk/interfaces/MultisigMetadata.html).

:::caution

The provider may not support multisig accounts, in which case a [`VIP030027MethodNotSupportedError`](../../api-reference/errors.mdx#vip030027methodnotsupportederror) **SHOULD** be returned.

:::

<Tabs
  defaultValue="javascript"
  values={[
    { label: 'Javascript', value: 'javascript' },
    { label: 'TypeScript', value: 'typescript' },
  ]}>
  <TabItem value="javascript">

  ```js
  const algosdk = require('algosdk');

  // create a transaction
  try {
    const algodClient = new algosdk.Algodv2(
      'aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa',
      'http://localhost',
      '4001',
    );
    const encoder = new TextEncoder();
    const multisigParams = {
      addrs: [
        'P3AIQVDJ2CTH54KSJE63YWB7IZGS4W4JGC53I6GK72BGZ5BXO2B2PS4M4U', // authorized in provider and will be used to sign
        '6GT6EXFDAHZDZYUOPT725ZRWYBZDCEGYT7SYYXGJKRFUAG5B7JMI7DQRNQ', // authorized in provider and will be used to sign
        'TKDBCV4SCSVR2GECXL7NJ5U34PDNLEIMFBTOYVURAPG53OXJLF4LEDSNGE', // not in provider
      ],
      threshold: 1,
      version: 1,
    };
    const multisigAddress = algosdk.multisigAddress(multisigParams);
    const suggestedParams = await algodClient.getTransactionParams().do();
    const transaction = algosdk.makePaymentTxnWithSuggestedParamsFromObject({
      amount: algosdk.algosToMicroalgos(1),
      from: multisigAddress,
      note: encoder.encode('Hello Human!'),
      suggestedParams,
      to: '6GT6EXFDAHZDZYUOPT725ZRWYBZDCEGYT7SYYXGJKRFUAG5B7JMI7DQRNQ',
    });
    const transactionBytes = transaction.toByte();
  } catch (error) {
    // handle error
  }

  // initialized client
  client.onSignTransactions(({ error, result }) => {
    if (error) {
      console.error('error:', error);

      return;
    }

    console.log(result);
    /*
    {
      stxns: [
        'gqNzaWfEQ...',
      ],
    }
    */
  });

  // send a sign transactions request
  client.signTransactions({
    params: {
      txns: [
        {
          msig: multisigParams,
          txn: btoa(String.fromCodePoint(...transactionBytes)), // convert to base64 string
        },
      ],
    },
    vcic: 'q5dQ...',
  });
  ```

## Signing transactions with re-keyed accounts

When attempting to sign a transaction using a re-keyed account, the `authAddr` field **MAY** be used to instruct the provider to use this address as the signer of the transaction.

Supplying the `authAddr` will override the sender address in the transaction field.

:::caution

The provider **MAY** not support re-keyed accounts, in which case the [`VIP030027MethodNotSupportedError`](../../api-reference/errors.mdx#vip030027methodnotsupportederror) **SHOULD** be returned.

:::
