## Overview

As a provider usually has access to the network, the `post_transactions` method allows clients to rely on the provider to send transactions to the network.

## Responding to a post transactions request

Once the provider object has been initialized, simply listen to events and respond:

<Tabs
  defaultValue="javascript"
  values={[
    { label: 'Javascript', value: 'javascript' },
    { label: 'TypeScript', value: 'typescript' },
  ]}>
  <TabItem value="javascript">

  ```js
  provider.onPostTransactions(({ challenge, params }) => {
    // ... using the `params.stxns` parameter, the provider posts the transactions to the network and returns the transaction ids

    return {
      result: {
        txnIDs: [
          'OKU6A2Q...',
        ],
      },
      signature: 'gqNzaWfEQ...', // this must be the result of the signing of the challenge using the vcic's private key
      vcic: vcic.config.credential.toString(),
    };
  });
  ```

  </TabItem>
  <TabItem value="typescript">

  ```typescript
  provider.onPostTransactions(({ challenge, params }) => {
    // ... using the `params.stxns` parameter, the provider posts the transactions to the network and returns the transaction ids

          'OKU6A2Q...',
  ```

  </TabItem>
</Tabs>

:::caution

If this method is not supported, then a [`VIP030027MethodNotSupportedError`](../../api-reference/errors.mdx#vip030027methodnotsupportederror) **SHOULD** be thrown.

:::

:::caution

If there is a group of atomic transactions, but the computed group ID doesn't match the assigned ID, then a [`VIP030027InvalidGroupIdError`](../../api-reference/errors.mdx#vip030027invalidgroupiderror) **SHOULD** be thrown.

:::

:::caution

If any of the transactions are malformed, then a [`VIP030027InvalidInputError`](../../api-reference/errors.mdx#vip030027invalidinputerror) **SHOULD** be thrown.

:::
