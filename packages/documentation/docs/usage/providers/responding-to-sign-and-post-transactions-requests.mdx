## Overview

If a provider is able to both sign & post transactions, this method can simply be implemented to allow clients to perform both these methods within one method.

## Responding to a sign and post transactions request

Once the provider object has been initialized, simply listen to events and respond:

<Tabs
  defaultValue="javascript"
  values={[
    { label: 'Javascript', value: 'javascript' },
    { label: 'TypeScript', value: 'typescript' },
  ]}>
  <TabItem value="javascript">

  ```js
  provider.onSignAndPostTransactions(({ challenge, params }) => {
    // ... using the `params.txns` parameter, the provider signs and posts the transactions to the network and returns the transaction ids

    return {
      result: {
        txnIDs: [
          'OKU6A2Q...',
        ],
      },
      signature: 'gqNzaWfEQ...', // this must be the result of the signing of the challenge using the vcic's private key
      vcic: vcic.config.credential.toString(),
    };
  });
  ```

  </TabItem>
  <TabItem value="typescript">

  ```typescript

    // ... using the `params.txns` parameter, the provider signs and posts the transactions to the network and returns the transaction ids
  ```

  </TabItem>
</Tabs>

:::caution

If this method is not supported, then a [`VIP030027MethodNotSupportedError`](/api-reference/errors#vip030027methodnotsupportederror) **SHOULD** be thrown.

:::

:::caution

If there is a group of atomic transactions, but the computed group ID doesn't match the assigned ID, then a [`VIP030027InvalidGroupIdError`](/api-reference/errors#vip030027invalidgroupiderror) **SHOULD** be thrown.

:::

:::caution

If any of the transactions are malformed, then a [`VIP030027InvalidInputError`](/api-reference/errors#vip030027invalidinputerror) **SHOULD** be thrown.

:::

:::caution

If the transactions fail to be accepted by the network, then a [`VIP030027FailedToPostSomeTransactionsError`](/api-reference/errors#vip030027failedtopostsometransactionserror) **SHOULD** be thrown.

:::
