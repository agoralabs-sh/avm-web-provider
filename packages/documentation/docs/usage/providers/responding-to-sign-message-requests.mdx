## Overview

As providers store the keys of an AVM account, they are able to sign some arbitrary bytes.

:::caution

Providers **MUST** ensure the bytes are either parsed in a pre-defined format, or they use the [`algosdk.signBytes`](https://algorand.github.io/js-algorand-sdk/functions/signBytes.html) which prepends a decoded `MX` to the beginning of the bytes.

:::

## Responding to a sign message request

Once the provider object has been initialized, simply listen to events and respond:

<Tabs
  defaultValue="javascript"
  values={[
    { label: 'Javascript', value: 'javascript' },
    { label: 'TypeScript', value: 'typescript' },
  ]}>
  <TabItem value="javascript">

  ```js
  provider.onSignMessage(({ challenge, params }) => {
    // ... using the `params.message` and the `params.signer` parameters, the provider signs the message with the private key of the signer and, with the signature, encodes as a base64 string

    return {
      result: {
        signature:  'gqNzaWfEQ...', // base64 encoded signature of the `algosdk.signBytes` result
        signer: 'P3AIQVDJ2CTH54KSJE63YWB7IZGS4W4JGC53I6GK72BGZ5BXO2B2PS4M4U',
      },
      signature: 'gqNzaWfEQ...', // this must be the result of the signing of the challenge using the vcic's private key
      vcic: vcic.config.credential.toString(),
    };
  });
  ```

  </TabItem>
  <TabItem value="typescript">


:::caution

If this method is not supported, then a [`VIP030027MethodNotSupportedError`](../../api-reference/errors.mdx#vip030027methodnotsupportederror) **SHOULD** be thrown.

:::

:::caution

If the signer, specified by `params.signer`, is not known, or not authorized, a [`VIP030027UnauthorizedSignerError`](../../api-reference/errors.mdx#vip030027unauthorizedsignererror) **SHOULD** be thrown.

:::
